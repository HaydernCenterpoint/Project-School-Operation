# Days 4–7 academic alpha

## Delivered flow

From a clean synthetic seed:

1. An Admin signs in on web, creates a class and assigns one seeded Teacher plus one or more seeded Students.
2. The assigned Teacher publishes a text assignment with an optional future due date.
3. Only enrolled Students can see the published assignment.
4. A Student submits 1–20,000 characters from the Expo app.
5. Retrying the same payload with the same idempotency key returns the original submission.
6. The assigned Teacher reads the submission and writes feedback.
7. The Student sees `submitted` or `reviewed` status and the feedback.

File and URL submission are intentionally unsupported.

## Trust boundaries

- Web and mobile use Supabase directly only for authentication/session lifecycle.
- Business requests use the Next.js BFF with the user's Bearer JWT.
- The BFF validates the JWT with Supabase Auth and derives membership from `auth.uid()`.
- Clients never provide a trusted `tenant_id`, actor ID or role.
- PostgreSQL RPCs are the atomic write boundary:
  - `create_class_with_members`
  - `save_assignment`
  - `submit_assignment`
  - `review_submission`
- Assignment and submission tables grant authenticated users `SELECT` only. Raw client DML is revoked.
- RLS remains active for every read, including BFF requests.
- No request path uses a service-role key.
- Audit events are generated by database triggers; clients cannot insert audit rows.
- Audit metadata contains identifiers and action names only, never assignment instructions, submission content or feedback.

## API surface

```text
GET  /api/classes
POST /api/classes
GET  /api/assignments?classId=<uuid>
POST /api/assignments
GET  /api/submissions?assignmentId=<uuid>
POST /api/submissions
POST /api/submissions/<uuid>/feedback
```

JSON mutation bodies use exact field allowlists. Text submission requires a UUID `Idempotency-Key` header. Multipart, unknown URL/file fields, blank text and text over 20,000 characters are rejected.

## Interface decisions

- The intact Sao Do University logo remains the source of visual identity.
- Navy frames navigation, cobalt communicates focus/selection, red is reserved for primary actions and yellow is a restrained orbital/keyline accent.
- Operational screens use open lists and panels rather than dashboard cards, charts or decorative metrics.
- The portal includes loading, empty, mutation, error and permission states with live-region announcements.
- Mobile keeps the existing three tabs and uses the stack path `Class → Assignment`.
- The mobile submission idempotency key is stored before the request and reused on retry.

## Current limitations

- This is a synthetic-data sandbox, not a real-user school pilot.
- One active membership per account is supported in this slice; multi-school context switching is not implemented.
- Account invitation/provisioning UI is not implemented; Admin assigns seeded identities.
- Student submission is text-only. Upload, URL attachment and rich text are out of scope.
- Admin cannot read submission content; only the assigned Teacher and submitting Student can.
- Android evidence is an Expo export. EAS credentials, an installable Preview build, physical-device smoke and TalkBack testing still require external accounts/hardware.
- Backup/restore has been exercised only on the disposable local sandbox; no staging/production restore drill has been completed.
- No staging/production deployment, UAT sign-off or operational monitoring has been completed.
- Web accessibility evidence does not replace Android physical-device and TalkBack testing.
- Database quotas cover membership and academic mutations, but gateway-level limits for GET, invalid JWT and attempts rejected before database mutation remain a staging gate.
- AI Tutor and all non-academic modules remain disabled. **AI is OFF** for the local hardening candidate.

These limitations keep the result labelled **Academic Alpha / local hardening sandbox**, not a production pilot.

Days 8–12 evidence, deploy/rollback/restore procedures and external sign-off gates are maintained in `docs/release-candidate.md`.
